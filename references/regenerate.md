# 重新切分（regenerate）

本技能只覆盖**重新切分**：源 `.d.ts` 已在项目里，脚本把它们切成小片并重建索引。
**重新生成 `.d.ts` 本身不在本技能范围内** —— 见文末。

## 何时重切

| 触发条件 | 处理 |
|---|---|
| 步骤 1 校验发现某源 `sha1` 与 manifest 不符 | 只重切**漂移的源**（不写 `--target` 即自动增量） |
| 符号查不到，且怀疑是新增类型 | 重切对应源（先看 `troubleshooting.md` 排掉其它成因） |
| manifest 缺失 / 损坏，或分片被删 | 全量重建 |
| 换了 `--threshold` | 全量重建（阈值改变的是全部分片边界） |
| 首次在项目里启用本技能 | 全量重建（此时没有 manifest） |

## 分目标调用（常规用法）

`--target` 一次只处理列出的源，**未列出的源一行都不动**。默认（不写 `--target`）是增量自愈：
逐源比对哈希，只重切漂移的源。

| 场景 | 命令 | 取舍理由 |
|---|---|---|
| 项目蓝图资产增删后 | `node split-dts.mjs --target bp` | `ue_bp.d.ts` 随蓝图资产变化，**高频**；不该因此碰其它源 |
| 引擎 / 插件版本变化后 | `node split-dts.mjs --target ue` | `ue.d.ts` 随引擎与模块变化，**低频** |
| Puerts 版本变化后 | `node split-dts.mjs --target decorators` | 装饰器声明随 Puerts 版本变化，**极低频** |
| 多个源一起漂移 | `node split-dts.mjs --target ue,decorators` | `--target` 接受逗号分隔的 id 列表 |
| 不确定哪个源漂移了 | `node split-dts.mjs` | 增量模式自己比哈希，只重切漂移的源 |

`--target` 的取值是源的短标识：`ue` / `bp` / `decorators` / `puerts` / `puerts-index` / `ffi` / `cpp` / `ue-index`。

**为什么分目标**：两个大源的漂移频率差一个量级 —— bp 随项目蓝图走，ue 随引擎走。
若为每次 bp 漂移都重切 ue，脚本要从"只读漂移源并装箱"变成"读入全部源、解析全部单元、重新装箱"，
代价与收益完全不成比例。分目标执行把这一步的成本压回与漂移源同量级。

**分目标不破坏其它源**：重切一个源时，只删除**该源**的孤儿分片（归属前缀互不重叠），
manifest 里属于其它源的行逐字段原样保留。所以分目标执行的结果与全量重建一致。

## 完整参数集

与 `node split-dts.mjs --help` 的输出**完全一致**：

| 参数 | 行为 |
|---|---|
| 无参数 | **增量**：逐源比对哈希，只重切漂移的源；全部已最新则打印 `unchanged` 后跳过 |
| `--target <ids>` | 只处理列出的源（逗号分隔）；**仍校验哈希**，未漂移则跳过（除非同时给出 `--force`） |
| `--all` | 全量重建，等价于 `--target <全部> --force` |
| `--force` | **与 `--target` 组合时**只强制重切列出的源（即使哈希未变）；**单独给出时强制全部源**，此时效果与全量重建相同 |
| `--project <path>` | 项目根；缺省由脚本自身位置**向上查找含 `tsconfig.json` 的最近目录**，查不到则响亮失败 |
| `--threshold <n>` | 片长阈值（默认 1800）。阈值变化会改变**全部**分片边界，故与 manifest 记录不同时所有源视为 stale、强制全量重建 |
| `--verify-only` | 不切分，只对现有产物跑自检（自检恒用 manifest 里记录的阈值，不比对命令行传入值） |
| `--no-verify` | 切分后跳过自检（**仅供排障**；默认总是自检） |
| `--help` | 打印用法并退出 0 |

退出码：`0` = 成功（含"未变、已跳过"）；非 `0` = 响亮失败，且**不留半更新的 manifest**。

## 分片命名

只有**被切分**的源会产出分片：`ue`、`bp`、`decorators`。其余源（`puerts` / `puerts-index` /
`ffi` / `cpp` / `ue-index`）不切分，在 manifest 里是 `sliced: false`、`frag` 直指原文件，没有分片。

分片名分**两种形态**，取决于该单元是否超过片长阈值：

| 源 | 常规（单元 ≤ threshold） | 例外（单元 > threshold，在单元内再切） |
|---|---|---|
| `ue` | `ue.NNN.d.txt` | `ue-<Name>-NNN.d.txt` |
| `decorators` | `decorators.NNN.d.txt` | `decorators-<Name>-NNN.d.txt` |
| `bp` | `bp-<root>-NNN.d.txt` | `bp-<包全路径>-NNN.d.txt` |

- `NNN` 是**占位符**（实际为补零的数字），`<Name>` 是声明名，`<root>` 是 **packageRoot**
  （package 全路径的第一个点分段）；`<包全路径>` 里的点写成连字符。
- ⚠️ **`bp` 与另两个源的形态不同**：`bp` 的常规片是**连字符 + root 段**（`bp-<root>-NNN`），
  不是 `ue.NNN` 这种点式。按点式去找 bp 的分片会找不到。
- **编号是同一源内共享的一个递增计数器**：常规片与例外片**共用**同一个计数器
  ⇒ 例外片的号**不**构成 `001` 起的独立序列，而是"轮到它时"的号。
  判据是"片名唯一且归属明确"，不是序号本身。
- **分片名只为定位而存在，不是稳定标识**：重切（哪怕只是多了一个蓝图）就可能让编号整体位移。
  故**不要缓存片名**、也不要把它写进需要长期稳定的地方 —— 权威定位依据始终是 `manifest.jsonl`。

> 归属前缀（孤儿清理的依据，三者两两互不重叠）：`ue` = `ue.` / `ue-`；`bp` = `bp-`；
> `decorators` = `decorators.` / `decorators-`。

## 强制全量重建的判据

以下任一成立时脚本**不**做局部重切，而是把所有源视为 stale：

| 判据 | 原因 |
|---|---|
| `threshold` 与 manifest 记录不同 | 阈值变化改变**全部**分片边界，局部重切会产出互相矛盾的分片集 |
| `__meta__` 版本号不同 | 记录结构可能已变 |
| manifest 不存在或损坏（首行非法 JSON / 无 `sources[]`） | 没有可信基线 |
| 某源不在 meta 的 `sources[]` 中 | 新增源，仅该源 stale |

## 产物与自检

- **写盘原子**：先写同目录临时文件再改名，故失败时不留半更新的 manifest。分片先写、manifest 后写。
- 默认在切分后自跑全量自检；`--verify-only` 可只跑自检。对产物应确认：分片内单元不跨片、
  分片长度不超阈值、manifest 与分片一致、`.fragments/` 里没有 `.d.ts`。
- 孤儿分片清理**严格限定在本目标内**：重切 bp 绝不触碰 ue / decorators 的分片。

## 本技能不做的事：重新生成 `.d.ts`

**不能**用本技能（也不能用任何命令行 / UAT / CI 流程）重新**生成** `.d.ts`：

- 生成入口是**引擎编辑器内的代码生成命令** `Puerts.Gen` —— 一个 `FAutoConsoleCommand`，
  只接受 `FULL` 与 `PATH=<包路径>` 两个参数（前者全量、后者限定包路径）。
- **不存在对应的 commandlet**，因此无法脱离 UE 编辑器调用，也无法在 CI 里自动化。
- 所以：源文件缺失或过期时，**先回到 UE 编辑器**（工具栏的 `puerts` 按钮 / 控制台命令）重新生成，
  生成完再回来用本技能重新切分。本技能只能对**已生成**的 `.d.ts` 重新切分。

> 顺带一提：把源文件当成"可以随时再生成"的东西是有代价的 —— 生成过程依赖编辑器里的反射数据，
> 版本不同产出的内容也不同。索引过期时的正确动作是重切（若源已更新）或回编辑器重生成（若源本身过期），
> 两者不要混为一谈。
